# iOS 16.6.1 兼容改造：验收标准与安全闸口

制定日期：2026-11-24（Asia/Taipei）。基线：上游 `sqlpxc/airhand` 提交 `08e2db0251760f04af40143f3d7409fdf9f16659`。

## 目标和范围

为已有 TrollStore 的 iOS 16.6.1 用户提供可安装的 arm64 IPA，保留远程控制与 ReplayKit 共享本机的既有能力。继续兼容 iOS 17 及以上。协议、服务器信任、端到端加密、输入语义、存储格式和广播权限边界保持一致。

实现限定为 iOS 状态观察兼容、旧系统 API 回退、Swift/Rust 部署版本和独立 GitHub Actions 构建验证。最低部署目标统一为 `16.6`。保留现有页面、文案、App Group、Bundle ID 和广播扩展；不增加私有权限、后台常驻、远程注入 iPhone 触摸等能力。默认服务器允许留空，用户安装后配置。

用户场景：安装 IPA 后配置服务器并控制电脑；正常使用配对、声音、输入和重连；需要时主动广播本机屏幕；以后更新 IPA 后保留设置与配对数据。

## 证据规则和闸口

状态仅使用 `PASS`、`FAIL`、`NOT RUN`、`BLOCKED`、`N/A`。每条结果记录提交 SHA、命令或手动步骤、环境、时间、退出码和证据位置。`N/A` 必须说明设备或场景不适用的原因。没有设备或 SDK 的项目必须记为 `NOT RUN/BLOCKED`，不能用代码检查、模拟器运行或编译成功替代真机通过。

| 闸口 | 必须满足的条件 | 允许的下一步 |
|---|---|---|
| G0 标准冻结 | 先记录本文件，确定范围、验收矩阵、安全约束和回滚方案 | 开始兼容实现 |
| G1 推送前自测 | 下方 G1 所有自动化及源码安全检查通过；工程师全局一致性检查通过；独立 QA 无未解决的阻塞问题 | 仅推送到个人 Fork 的兼容分支，触发候选 IPA 构建 |
| G2 CI 候选包 | 固定工具链的设备 Release 编译、测试及 IPA 静态校验全部通过 | 交付带 SHA256、提交 SHA 的候选 IPA，标记“待真机验收” |
| G3 真机验收 | 在用户 iOS 16.6.1 + TrollStore 上执行完整 P0 功能矩阵；新系统基本回归完成或明确记录未执行 | 标记对应环境“已验证兼容” |

本机环境只有 Command Line Tools、Swift、Rust 和 XcodeGen，没有完整 Xcode、iOS SDK、模拟器或用户手机。G1 验证可移植的核心行为及改动边界，**不代表已经执行 iOS App 功能测试**。iOS 编译放在 G2，手机交互放在 G3；因此 G1 后的推送仅供 CI 生成候选包，不表示正式发布验收通过。

阻塞规则：安装/启动失败、任一核心功能无法使用、证书信任或权限扩大、敏感数据泄漏、P0 用例失败、CI 失败、产物身份或最低系统不符均为阻塞问题。阻塞问题禁止越过所属闸口。没有执行的 P0 真机用例阻塞 G3，但不伪装成 G1 的已通过用例。非阻塞的图标或动画差异必须登记；状态不刷新、错误提示失效、键位卡住不属于外观差异。

## 安全闸口（G1 审查，G2 产物再验证）

| ID | 约束和拒绝条件 |
|---|---|
| S01 身份与加密 | 不关闭 TLS/QUIC 证书验证、主机密钥检查、配对确认或端到端加密；固定指纹不匹配时必须拒绝。空指纹继续沿用原有首次信任保存机制，不能变成每次无条件信任。 |
| S02 最小权限 | 保留原 App Group 权限和扩展属性。主 App 与扩展的 group 必须相同；不增加 `platform-application`、无沙盒、调试附加、动态签名等权限。Release 产物不得带 `get-task-allow=true`。 |
| S03 用户主动授权 | 麦克风只能由原有用户操作触发，拒绝权限后可继续使用其余功能；共享屏幕继续经系统广播选择器主动开启；不绕过权限或使停止按钮失效。 |
| S04 数据边界 | 保留 App Group 共享存储、原有文件保护和序列化格式；没有 Group 时显示限制并安全回退。剪贴板、文件保存、发送与读取保留既有用户触发规则；路径遍历/越界文件名不得逃出目标目录。 |
| S05 日志与仓库 | 不记录配对码、会话令牌、私钥、剪贴板内容、文件正文或用户身份材料；不上传本地设置/身份文件；不输出 GitHub token。服务器地址和公开证书指纹可以作为可选配置，不应混入任何私人凭据。 |
| S06 Actions 权限 | 新工作流默认 `contents: read`；不使用 `pull_request_target`、不执行外部 PR 的高权限代码、不自动发布 Release、不申请仓库写权限；只构建本 Fork 的授权兼容分支或手动选定提交。 |
| S07 供应链 | 第三方 Actions 锁定不可变提交 SHA并注明版本；Perception 固定经过验证的稳定版本，提交 `Package.resolved` 并在CI验证锁定结果；Rust 使用 `--locked`；不从不明 URL 执行脚本。工具链版本和下载源写入日志。 |
| S08 产物可信性 | CI Summary 给出源码 SHA、Xcode/Swift/Rust/依赖版本、构建配置、最低系统、架构、IPA SHA256；包由该提交构建，校验失败不上传“可安装候选包”。 |

## 变更与回滚

只在个人 Fork `zcp1997/airhand` 的 `compat/ios-16.6` 分支提交；不直接推送 `main`、不修改原作者仓库、不强推、不自动创建公开 Release、不执行任何外部部署。每次修复都记录新的提交 SHA 并重新执行受影响的闸口；不能把旧提交测试结果移用到新包。最终交付说明必须并列列出 G1/G2/G3 状态与未执行项。

保留基线提交和上一次已验证 IPA。候选包失败时停止标记可用，修复后重建；用户可用 TrollStore 覆盖安装前一兼容版本。优先覆盖更新，避免卸载导致 App Group 数据和身份丢失。不得声称上游 iOS17+ IPA 可作为 iOS16 的运行回滚包；若尚无旧兼容包，回滚仅指源码恢复，设备上没有已验证包可退。
